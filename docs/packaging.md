# Формат, оформление и публикация

Пакет использует нативный формат Hermes: корневой `plugin.yaml` с
`manifest_version: 2` и точку входа `__init__.py`. Функция `register(ctx)`
регистрирует два skill и CLI-команду `senler` через публичный API плагинов.
Импорт и включение плагина не запускают вход и не изменяют MCP-настройки.

Hermes отдаёт приоритет `plugin.yaml`. Дополнительный `plugin.json` сохранён
как метаданные и переносимый вариант skills формата Agent Plugins v1.
Он сам по себе не предоставляет нативную команду подключения.

`mcp-server.json` — собственный файл настроек этого плагина: имя MCP, HTTPS-адрес,
OAuth и таймаут подключения. Это не стандартный переносимый `mcp.json`, который
в проверенной версии Hermes не поддерживает параметр `auth: oauth`.
`hermes senler connect` читает эти настройки и вызывает штатные MCP-команды
Hermes в том же Python и профиле. Hermes выполняет вход, хранит токены и
сохраняет подключение. Плагин не читает токены и не переписывает `config.yaml`.
Существующее совместимое подключение проверяется без замены настроек.
Hermes может запросить вход, если сохранённая авторизация больше не работает;
`--reauthorize` принудительно запускает новый вход через штатную команду Hermes.

## Логотип

`assets/icon.svg` — исходный логотип Senler, совпадающий с SVG пользовательского
плагина Senler для Codex. Цвет — `#0299E0`. README использует относительную ссылку,
чтобы изображение работало в распакованном пакете и в GitHub-репозитории.
Установщик сохраняет каталог `assets` вместе с README.

В схеме Agent Plugins 1.0.0 нет полей `icon`, `logo` или Codex-поля `interface`.
Добавление таких полей нарушило бы схему. Hermes также не объявляет расширение
манифеста для значка переносимого плагина. Поэтому наличие логотипа в пакете не
гарантирует его отображение рядом с установленным плагином в Desktop.

Для картинки карточки официального каталога Hermes используется `image` в
отдельной записи `plugin-catalog/<name>.yaml` репозитория Hermes. При подготовке
публикации нужно оформить изображение в пропорции 2:1 и указать HTTPS-ссылку на
GitHub с тем же полным commit SHA, на который закреплена запись каталога.
Квадратный SVG из пакета является исходным логотипом, а не готовым баннером 2:1.
Исходники публикуются в [SenlerBot/senler-io-user-hermes-plugin](https://github.com/SenlerBot/senler-io-user-hermes-plugin),
тестовые выпуски — в GitHub Releases. Запись в официальном каталоге Hermes пока
не создана; установка из GitHub выполняется напрямую по README.

## Границы проверки

Формат и API регистрации сверены с официальной схемой и исходниками Hermes на
коммите `0d3b0348f5aab2bc263c81b660d761a76ded14fe` от проверки 10 октября 2026.
Проба из `hermes_cli/plugin_validate.py` импортирует пакет и вызывает `register`
в отдельном процессе с записывающим контекстом. Полная команда
`hermes plugins validate <path>` запускается установщиком в пользовательском
Hermes до копирования файлов. Локальные PowerShell-тесты заменяют CLI тестовой
командой; это не запуск полноценного Hermes.

Это проверка формата и локальной установки, а не подтверждение работы OAuth,
отображения в конкретной версии Desktop или обработки реального вебхука.
Сквозная проверка выполняется по [windows-test.md](windows-test.md).

Помощник вебхуков использует внутренние функции Hermes для атомарного изменения
подписок. Они не входят в публичный контракт плагинов: обновление Hermes требует
повторной проверки помощника. Соответствие формату пакета само по себе не означает
гарантии совместимости со всеми будущими версиями или допуска в каталог.
