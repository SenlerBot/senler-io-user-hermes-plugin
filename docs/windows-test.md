# Проверка на Windows

Используйте отдельный учебный проект Senler и свой канал.
Новые поля вебхуков должны присутствовать в используемом User MCP; ZIP сам не
развёртывает серверные изменения.

1. Установите и включите пакет по README. В `hermes plugins list` найдите
   включённый `senler-io-user`. Запустите `hermes senler connect`: адрес MCP
   вводить не нужно. Пройдите вход и дождитесь успешной проверки; выполните
   `hermes senler check`. Повторный `connect` должен сохранить настройки и
   выбранные инструменты без повторной регистрации. В отдельном тестовом профиле
   проверьте отмену входа: сообщение об успехе не должно появиться.
2. Откройте новый чат. Попросите найти skills пакета через `skills_list`, показать
   доступные проекты и прочитать известный диалог без записи. Сверьте с Senler.
   Перезапустите Hermes и повторите чтение: сохранённый OAuth должен работать.
3. Попросите Hermes обрабатывать `message_new` и ещё один тип событий учебного
   проекта, записывая краткий отчёт о каждом событии. Он должен создать тип Hermes без URL,
   получить scoped ключ через MCP и включить свою платформу. При первом запуске
   проверьте старт или перезапуск gateway этого профиля. Публичный IP и туннель
   не запрашиваются. В Senler после проверки подписка включится сама.
4. Выполните `hermes senler relay status`. В выводе видны ID подписки и проект,
   но нет ключа. В новом чате повторная просьба должна использовать тот же webhook.
   Измените набор событий в Senler: Hermes должен получить изменения автоматически.
   В новом чате попросите добавить условие обработки: прежние правила должны
   сохраниться, новое условие добавиться, повторный вход не запрашиваться.
   При изменении правил во время обработки начатая попытка должна остановиться,
   ожидающие события — использовать новые правила. Возврат прежних правил не
   возобновляет отменённое задание; сохранение того же текста работу не прерывает.
5. Создайте учебное событие. В истории Senler должны последовательно появиться
   «Получено», «Обрабатывается» и отчёт обработки. Сообщения клиентам не отправляются,
   поскольку в этом сценарии пользователь попросил только отчёт.
   Пробы подключения не запускают ИИ и не вызывают MCP. Проверяйте реальный
   итог обработки отдельно от успеха соединения.
   В отдельном тестовом профиле повторите событие с недоступной моделью или неверной
   авторизацией провайдера: доставленный текст ошибки не должен давать «Обработано».
   Ожидается «Ошибка» с причиной либо пояснением, что завершение не подтверждено.
   Прервите начатую обработку после передачи части отчёта плагину: в результате
   должны сохраниться причина остановки и принятый текст с пометкой частичного
   отчёта. Повторите с паузой и с аварийной остановкой gateway: после запуска
   текст должен восстановиться из базы, автоматического повторения действий
   быть не должно. Текст, который модель ещё не передала плагину, не восстанавливается.
   Повторите с включённым потоковым выводом Hermes: итоговый текст должен попасть
   в отчёт один раз, без курсора и склеенных обрывков слов. Завершённые промежуточные
   сообщения при прерывании должны сохраниться.
6. Остановите gateway, создайте ещё одно событие, затем запустите gateway.
   Подписка должна переподключиться и получить ожидающее событие. Проверьте
   смену сети/IP. Выключенный компьютер не обрабатывает события.
   Краткий обрыв до запуска обработки должен оставить событие в ожидании.
   Готовый отчёт после восстановления связи доставляется без повторного задания.
   При двух подписках проверьте недоступность подключения одной из них: готовый
   отчёт второй должен доставляться, пока первая пытается подключиться.
7. Поставьте подписку на паузу и перезапустите Hermes. Пауза должна сохраниться.
   Повторите локальную остановку при недоступном MCP: локальная очередь не должна
   начинать новые задания, а незавершённое отключение Senler должно быть явно
   сообщено. Обновление настроек не должно снимать паузу. Уже отправленное действие
   может завершиться; новые вызовы инструментов должны блокироваться.
   Уже сохранённый отчёт должен появиться в истории Senler без снятия локальной
   паузы. Если связь была потеряна, восстановите её и проверьте доставку отчёта:
   новое задание модели запускаться не должно.
   Во время обработки быстро выключите и снова включите подписку: старая попытка
   должна остаться отменённой, а ожидающие события — продолжить обработку.
8. Попробуйте подключить ту же подписку со второго профиля: нужен явный сброс
   подключения в Senler. После сброса старый ключ не работает. Подключите новый
   профиль и проверьте, что две установки не обрабатывают одну подписку вместе.
9. Отзовите разрешение пользователя на управление вебхуками и убедитесь, что
   соединение закрывается. Затем восстановите право и выполните штатное
   переподключение. OAuth-токены не копируются вручную.
10. В учебном диалоге задайте правило отправки одного ответа. Проверьте ключ
    защиты от дублей при повторном вызове. Перезапуск после начала обработки
    должен показать прерывание для проверки, без автоматического повторения действий.
11. В отдельном тестовом профиле с `gateway.proxy_url` или `GATEWAY_PROXY_URL`
    настройка, возобновление и запуск входящих должны сообщать, что агент и плагин
    нужны в одном экземпляре Hermes. Адрес удалённого экземпляра в ошибке не выводится.
    Обычный облачный провайдер модели должен работать без этого ограничения.
    Для проверки защиты от смены настроек во время работы включите `gateway.proxy_url`
    в тестовом профиле при работающем gateway, когда задание не выполняется.
    Следующее учебное событие должно ждать, а `hermes senler relay status` — показать
    причину в `processing_blocked_reason`. Уже готовые отчёты должны доставляться.
    После удаления настройки ожидающее событие должно продолжиться автоматически,
    если его срок не истёк. Повторите с ручной паузой подписки: она должна сохраниться.
    В обычной работе место выполнения агента меняйте с остановкой и запуском gateway.

Проверка установщика с тестовой командой не заменяет этот сценарий в настоящем
Hermes. Сначала серверные изменения Senler API и User MCP должны быть развёрнуты.
