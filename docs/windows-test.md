# Проверка на Windows

Используйте отдельный учебный проект Senler и свой канал. Начните с черновиков.
Новые поля вебхуков должны присутствовать в используемом User MCP; ZIP сам не
развёртывает серверные изменения.

1. Установите пакет и выполните OAuth-вход по README. В `hermes plugins list`
   найдите включённый `senler-io-user`, затем запустите `hermes mcp test senler-io-user`.
2. Откройте новый чат. Попросите найти skills пакета через `skills_list`, показать
   доступные проекты и прочитать известный диалог без записи. Сверьте с Senler.
   Перезапустите Hermes и повторите чтение: сохранённый OAuth должен работать.
3. Выполните однократную настройку из [webhooks.md](webhooks.md). Проверьте, что
   `preflight` показывает нужный home, настроенный MCP и здоровый gateway.
4. Попросите обрабатывать `message_new` и ещё один подходящий тип события только
   учебного проекта, в режиме черновиков. Проверьте в Senler, что после тестов
   вебхук включён без дополнительной просьбы. Секрет не должен появляться в ответе.
5. Откройте новый чат и повторите просьбу или измените текст инструкции. Должен остаться тот же ID
   вебхука, без новой подписки. Укажите один канал и проверьте, что события
   остальных каналов не вызывают обработку.
6. Создайте одно реальное событие в учебном канале. Попросите в обычном чате:
   «Покажи последние черновики обработки Senler этого проекта». Откройте ссылку
   на найденную сессию и проверьте правильный проект, событие, черновик и отсутствие
   отправленного сообщения. Журнал содержит лишь начало ответа. Тестовый
   `test: true` должен завершиться без MCP-действий. Повторите с длинным сообщением:
   ID события и диалога должны сохраниться, даже если JSON обрезан.
7. Остановите туннель и повторите подключение. Проверка должна завершиться
   ошибкой, вебхук — остаться выключенным. Восстановите адрес и повторите:
   после успешных тестов включение должно произойти автоматически.
8. Попросите приостановить обработку: статус Senler disabled, локальный маршрут
   выключен. Попросите возобновить: новые тесты и включение того же ID.
   Отдельно повторите остановку при выключенном туннеле. Для проверки потери
   OAuth используйте отдельную учебную установку: локальная остановка должна
   работать, а статус Senler обозначаться как неподтверждённый.
9. Для проверки отправки отдельно разрешите **один ответ в учебном диалоге**.
   Убедитесь, что используется стабильный `idempotency_key`. Повтор с тем же
   ключом и содержимым не должен создавать второе сообщение. Не проверяйте это
   на реальных клиентах. Этот тест выполняется только по вашему разрешению.
10. После проверки отключите учебную интеграцию. Удаляется только её вебхук и
    принадлежащий плагину маршрут; другие маршруты и MCP должны сохраниться.

При обновлении с 0.2.0 сначала перенастройте существующий сценарий через Hermes:
новая версия включает инструкцию в сам маршрут. Проверьте, что сохранился ID
вебхука и произошли новые тесты перед автоматическим включением.

При сбое сохраните версию Hermes, этап, код/текст ошибки и результат preflight.
Не передавайте OAuth-токены, секрет подписи, полный config.yaml или файл
webhook_subscriptions.json. HTTP 202 означает приём, а не завершение задачи;
перезапуск после такого ответа может прервать обработку.
