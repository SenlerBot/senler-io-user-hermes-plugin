# Приём событий в Hermes

Нужен актуальный Hermes с native OAuth, нативными плагинами, динамическими
webhook-подписками и проверкой Standard Webhooks. Настройка выполняется в том же
каталоге `HERMES_HOME`, где установлен плагин. Эта версия поддерживает отдельный
gateway выбранного каталога; режим `gateway.multiplex_profiles` не поддерживается.

## Один раз после установки

1. Подключите `senler-io-user` через OAuth по README и выполните
   `hermes mcp test senler-io-user`.
2. Подготовьте публичный HTTPS-адрес, направленный к webhook-listener Hermes.
   При новой настройке помощник использует `127.0.0.1:8644`. Если порт уже задан,
   он сохраняется. `localhost` Windows недоступен серверу Senler: нужен настроенный
   туннель или reverse proxy с устойчивым адресом. Плагин не создаёт этот адрес.
3. Откройте PowerShell в папке установленного плагина. Для обычной Windows-установки
   или каталога из `HERMES_HOME`:

   ```powershell
   $senlerHermesHome = if ($env:HERMES_HOME) { $env:HERMES_HOME } else { Join-Path $env:LOCALAPPDATA 'hermes' }
   Set-Location (Join-Path $senlerHermesHome 'plugins\senler-io-user')
   ```

   Если Desktop использует другой профиль, укажите фактическую папку плагина
   в этом профиле. Для ZIP-установки команды можно выполнить и из распакованной
   папки. Настройте приём:

   ```powershell
   .\skills\senler-io-user\scripts\run-helper.ps1 provision -EnableAutomation -PublicBaseUrl 'https://your-existing-public-host.example'
   hermes gateway restart
   .\skills\senler-io-user\scripts\run-helper.ps1 preflight
   ```

   Замените адрес на настоящий. Если gateway ещё не запущен, используйте
   `hermes gateway start`. Автозапуск Windows настраивается отдельно штатной
   командой `hermes gateway install`, если он вам нужен.

   Если Python не найден рядом с `hermes.exe`, добавьте
   `-PythonPath 'C:\path\to\hermes-agent\.venv\Scripts\python.exe'` с фактическим
   путём вашей установки. Помощнику нужны модули Hermes. Для другого каталога
   сначала задайте `$env:HERMES_HOME`.

`-EnableAutomation` — явное разрешение владельца на использование
`mcp-senler-io-user` в обработчиках этого плагина. Оно не включает терминал,
файловые инструменты или MCP других серверов. Остальные маршруты и настройки
сохраняются. Gateway и доступный адрес должны работать всё время обработки;
сон или выключение Windows прекращает приём.

## Дальше — через обычную просьбу

> Обрабатывай входящие сообщения проекта «Учебный», только из канала «Поддержка».
> Определи тему и подготовь черновик ответа, без отправки клиенту.

Hermes выяснит ID через User MCP, создаст выключенный вебхук с нужными событиями,
настроит собственный маршрут и отправит синтетический тест каждого события.
После подтверждения приёма **сразу включит подписку**. Отдельно просить включение
не нужно. При ошибке подписка останется выключенной с объяснением причины.

Поддерживаются события из актуального каталога Senler: сообщения, нажатия
кнопок, подписки, изменения лидов, ошибки доставки и автоматизации. Точные
условия и действия задаются вашей инструкцией. Отправка клиенту разрешается
явной политикой; в начальном сценарии создаются только черновики.
Результаты остаются в сессиях обработки Hermes. Попросите в обычном чате:
«Покажи последние черновики обработки Senler этого проекта». Плагин получает
маркер нужного сценария и находит сохранённые ответы через `session_search`.
Ссылка на найденную сессию позволяет открыть её целиком. Если сохранённого
ответа нет, Hermes должен сообщить об этом, а не повторять обработку события.

`deliver: log` выводит только первые 200 символов ответа в журнал gateway.
Это не полный черновик и не автоматическое сообщение в чат, где вы настраивали
подписку. Черновик в Senler при этом не создаётся. Доставка результатов в
другой чат требует отдельной настройки получателя в Hermes.

Команды «проверь подключение», «измени правила», «приостанови обработку» и
«отключи эту интеграцию» используют сохранённое соответствие между маршрутом
Hermes и ID вебхука. В новом чате список подключений читается из локальных
настроек, поэтому помнить внутреннее имя сценария не нужно. Повторная настройка
не должна создавать новую подписку.

Остановка сначала выключает локальный приём, затем отключает подписку в Senler.
Если доступ к Senler потерян, результат обозначается как «остановлено локально»:
Senler ещё может пытаться доставлять события, но этот маршрут их не принимает.
Для остановки не нужно восстанавливать публичный адрес. Уже запущенная задача
при этом не отменяется. При отключении связи локальное соответствие удаляется
только после подтверждённого удаления вебхука из Senler.

Если MCP ещё не показывает поля `signature_scheme`, `status` при создании и
`event_type` в тесте, серверные изменения Senler ещё не применены. Плагин
останавливает настройку до создания несовместимого подключения.

## Что проверяется

Standard Webhooks — открытая спецификация подписи HTTP-запросов, а не формат
содержимого событий. Событие остаётся обычным JSON Senler.

| Заголовок | Значение |
| --- | --- |
| `webhook-id` | Стабильный `event_id`, в том числе при повторе |
| `webhook-timestamp` | Время попытки в Unix-секундах |
| `webhook-signature` | `v1,` и Base64 HMAC-SHA256 от `id.timestamp.rawBody` |

Ключ — Base64-декодированная часть `webhook_secret` после `whsec_`. Подписываются
точные отправленные байты. Старый формат Senler v1 сохраняется для существующих
получателей; для нового подключения плагин выбирает `standard-webhooks`.

Тест содержит `test: true` и не содержит реальных ID клиентов или диалогов.
Его обработчик не вызывает MCP и не отправляет сообщения, но запуск модели
Hermes может расходовать токены. Помощник проверяет HTTP 202, `accepted`,
маршрут, тип события и ID доставки. HTTP 200 с `ignored` не считается успехом.

Инструкция обработки включается прямо в локальный маршрут: загрузчик вебхуков
Hermes и каталог skills плагинов сейчас используют разные списки. Фоновому
обработчику не нужны инструменты файлов или загрузки других skills. ID проекта,
события и диалога передаются отдельно от JSON, который Hermes может обрезать.
После изменения инструкции или обновления пакета нужна повторная настройка с
новыми тестами; включение по-прежнему выполняется автоматически.

Это проверка подписи и приёма события. Завершение задачи модели, права на
конкретное действие и качество ответа проверяются отдельным реальным событием.
Кеш повторов Hermes хранится в памяти; он не обеспечивает восстановление всех
незавершённых задач после аварии. Для повторной отправки ответа skill использует
стабильный `idempotency_key` Senler. Отдельные входящие события одного диалога
могут обрабатываться одновременно: гарантированная последовательная обработка
потребует отдельной очереди и журнала результатов.
