# События Senler в Hermes

В разделе вебхуков Senler выберите тип **Hermes**, название и события. Поле URL
для этого типа не нужно. После создания появятся адрес подключения и статус
«Ожидает Hermes».

Установите плагин и выполните `hermes senler connect` один раз для своего
пользователя. Затем попросите Hermes подключить созданную подписку или настроить
обработку выбранных событий самостоятельно. Он найдёт проект через MCP, создаст
или выберет подписку, получит доступ только к ней и сохранит правила обработки.

Hermes устанавливает исходящее защищённое WebSocket-соединение с Senler.
Статический IP, туннель и входящий порт на компьютере не требуются. Сам адрес
не является секретом; ключ выдаётся авторизованному пользователю и хранится
локально в профиле Hermes. OAuth-токенами по-прежнему управляет сам Hermes.

После первой проверки всех выбранных типов событий подписка включается
автоматически. Проверка не вызывает ИИ и не отправляет сообщения клиентам.
При первом включении платформы нужно запустить или перезапустить gateway этого
профиля. Дальнейшие настройки подписок он подхватывает сам.

**Для своевременной обработки должны работать компьютер и Hermes gateway.**
Смена IP не мешает подключению. При обрыве связи плагин переподключается, Senler
держит до 1000 незавершённых событий на подписку до 24 часов с постановки в очередь,
включая события, уже полученные компьютером. Переподключение не
отменяет ручную паузу. При переполнении новые события пропускаются; счётчик и причина видны в карточке подписки. На одном профиле поддерживается до восьми подписок,
локальная очередь ограничена 1000 ожидающими событиями. Один gateway обрабатывает
события последовательно; несколько gateway в одном профиле не допускаются.

В истории Senler «В очереди» означает ожидание доставки, «Получено» — запись в
локальную очередь Hermes, «Обрабатывается» — начало выполнения. «Обработано» означает,
что Hermes подтвердил завершение запуска без ошибки и прерывания, а плагин сохранил
отчёт. Сбой, прерывание или отсутствие подтверждения дают «Ошибка» с пояснением
и доступным текстом отчёта. Этот статус описывает запуск Hermes; выполнение конкретного
действия проверяется по ответу Senler API. «Срок истёк» — результат не пришёл за срок хранения. Отчёт ограничен
16 000 символами; полный ответ остаётся в сессии Hermes. История хранится семь
дней. После сбоя событие может прийти повторно, но готовый результат отправляется
без повторной обработки. Прерванная попытка требует проверки уже выполненных
действий. Для одного ответа плагин сохраняет параметры и подставляет постоянный
ключ защиты от повторной отправки.

Обрыв до начала обработки оставляет событие в ожидании: плагин восстанавливает
подтверждение той же попытки и продолжает после подключения, пока не истёк срок
хранения. Если потерялся только отчёт, повторяется доставка сохранённого отчёта.
Пауза одного подключения не задерживает отчёты остальных.

Каждая принятая часть отчёта сразу сохраняется на компьютере в пределах лимита
16 000 символов. При паузе, изменении правил или перезапуске после сбоя итог содержит
причину остановки и уже сохранённый текст с пометкой «частичный отчёт».
Запоздавший текст остановленного задания не меняет итог и не попадает в следующее
задание. Сохраняется только текст, который Hermes успел передать плагину;
по нему нельзя гарантировать, что перечислены все выполненные действия.

Пауза сохраняет отмену начатой попытки и останавливает последующие вызовы инструментов;
уже отправленное действие может завершиться. Повторное включение продолжает очередь
ожидающих событий, отменённая попытка автоматически не запускается.
Для другого компьютера сбросьте подключение в Senler и привяжите
новую установку. Старый ключ перестанет работать. Изменение набора событий
синхронизируется автоматически и сохраняет ручную паузу. Правила обработки
задаются обычной просьбой пользователя; отдельного переключателя режимов нет.
При просьбе изменить правила Hermes сначала читает сохранённые инструкции
командой `relay instructions`, затем обновляет их через `relay update-instructions`.
Повторный вход и пересоздание вебхука для этого не нужны; ручная пауза сохраняется.
При изменении правил начатая попытка останавливается, ожидающие события используют
новые правила. Возврат прежнего текста не возобновляет отменённую попытку;
повторное сохранение тех же правил не прерывает работу.

Команды проверки без вывода ключей:

```powershell
hermes senler check
hermes senler relay status
```

Настройка из чата описана в [инструкции для Hermes](../skills/senler-io-user/references/hermes-relay-setup.md).
